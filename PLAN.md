# PLAN.md

# Wikeep Chrome Extension — Nix Flake Development Setup (macOS / Apple Silicon)

## Goal

Add a **reproducible** Nix flake development environment to the `drunkod/wikeep`
Manifest V3 Chrome extension so any contributor can:

- clone the repo and enter a pinned dev shell (`nix develop`),
- install npm dependencies,
- run TypeScript checks and Vitest tests,
- build the extension into `dist/`,
- validate Manifest V3 assumptions against the **built** manifest,
- launch Google Chrome on macOS with the unpacked extension loaded,
- package `dist/` as a ZIP for the Chrome Web Store,
- ship the change as a normal Git branch + Pull Request.

Primary target: **macOS on Apple Silicon (`aarch64-darwin`)**. The flake stays
cross‑platform safe so Linux contributors and CI also work, but the documented
happy path is macOS.

> Scope note: This is a tooling/DX change only. It does **not** touch extension
> runtime behavior, React components, TypeScript source, permissions, or
> DeepWiki capture logic (see `HOW_WIKEEP_WORKS.md`).

---

## What changed vs. the original plan

The original plan was structurally good but had correctness gaps. This revision fixes them:

| # | Issue in original | Fix in this plan |
|---|---|---|
| 1 | Called the setup "pinned" but never committed `flake.lock`. `nixos-unstable` floats. | Commit `flake.lock`. Pinning comes from the lock file, not the URL. |
| 2 | `npm test` → `vitest run` exits non‑zero when there are **no** test files, breaking `wikeep-check`. | Use `vitest run --passWithNoTests` (via a guarded `npm test` call). |
| 3 | `npm ci` hard‑fails if `package-lock.json` is missing or out of sync. | Detect the lockfile; fall back to `npm install` with a clear warning. |
| 4 | Validated `public/manifest.json`, but Chrome loads `dist/manifest.json`. The source is a template; the built one is the source of truth. | `wikeep-check` validates the **built** `dist/manifest.json` (after a build); MV3 field checks run there. |
| 5 | Manifest checks hard‑coded `background.js` / `sidepanel.html` filenames; brittle if the build renames outputs. | Assert structural invariants (MV3 version, service worker exists, side panel path exists) rather than exact incidental strings where possible. |
| 6 | `chromium` is unsupported/broken on `aarch64-darwin`; plan added it but darwin launch relied on system Chrome anyway. | On macOS, do **not** build Chromium via Nix. Launch the system **Google Chrome** via `open -a`. Chromium stays Linux‑only. |
| 7 | Delivery via GitHub Contents API (base64 PUTs) is fragile, skips `flake.lock`, and creates serverside commits with no local validation. | Use standard `git` + `gh pr create`. Simpler, validated locally, includes `flake.lock`. |
| 8 | `nix flake check` was in CI but the flake exposed no `checks`; behavior was incidental. | Document that `nix flake check` evaluates/builds the dev shell and runs shellcheck on the `writeShellApplication` helpers; that is the intended check. |
| 9 | `.envrc` used `use flake` with no caching guidance — slow re‑evaluation on every `cd`. | Recommend `nix-direnv` (`use flake` cached) and note plain `direnv` still works. |

## File 1: `flake.nix`

Create at the repository root.

```nix
{
  description = "Wikeep Chrome extension development environment";

  inputs = {
    nixpkgs.url = "github:NixOS/nixpkgs/nixos-unstable";
  };

  outputs = { nixpkgs, ... }:
    let
      systems = [
        "aarch64-darwin" # primary target (Apple Silicon)
        "x86_64-darwin"
        "x86_64-linux"
        "aarch64-linux"
      ];

      forAllSystems = nixpkgs.lib.genAttrs systems;
    in
    {
      devShells = forAllSystems (system:
        let
          pkgs = import nixpkgs { inherit system; };
          node = pkgs.nodejs_22;

          # Chromium is only built via Nix on Linux. On macOS we use the
          # system Google Chrome through `open -a` (see wikeep-open-chrome).
          linuxBrowserPackages =
            pkgs.lib.optionals pkgs.stdenv.isLinux [ pkgs.chromium ];

          # Shared install step: prefer reproducible `npm ci`, but don't hard
          # fail when a lockfile is missing.
          npmInstall = ''
            if [ -f package-lock.json ]; then
              echo "Installing dependencies with npm ci..."
              npm ci
            else
              echo "WARNING: package-lock.json not found; using npm install."
              echo "Commit a lockfile for reproducible installs."
              npm install
            fi
          '';

          # Run tests but don't fail the pipeline when no tests exist yet.
          npmTest = ''
            echo "Running tests..."
            npm test -- --passWithNoTests
          '';

          # Validate the BUILT manifest (the one Chrome actually loads).
          manifestChecks = ''
            echo "Checking built Manifest V3 (dist/manifest.json)..."
            test -f dist/manifest.json || {
              echo "dist/manifest.json missing; build did not run."; exit 1; }
            jq -e '.manifest_version == 3' dist/manifest.json >/dev/null
            jq -e '.background.service_worker | type == "string"' dist/manifest.json >/dev/null
            jq -e '.side_panel.default_path | type == "string"' dist/manifest.json >/dev/null
            echo "OK: MV3 manifest invariants hold."
          '';

          wikeep-check = pkgs.writeShellApplication {
            name = "wikeep-check";
            runtimeInputs = [ node pkgs.jq ];
            text = ''
              set -euo pipefail
              ${npmInstall}
              echo "Running TypeScript check..."
              npm run typecheck
              ${npmTest}
              echo "Building (needed to validate dist/manifest.json)..."
              npm run build
              ${manifestChecks}
              echo "OK: typecheck, tests, build, and manifest checks passed."
            '';
          };

          wikeep-build = pkgs.writeShellApplication {
            name = "wikeep-build";
            runtimeInputs = [ node pkgs.jq pkgs.zip ];
            text = ''
              set -euo pipefail
              ${npmInstall}
              echo "Running TypeScript check..."
              npm run typecheck
              ${npmTest}
              echo "Building extension..."
              npm run build
              ${manifestChecks}
              echo "Packaging extension..."
              rm -f wikeep-extension.zip
              ( cd dist && zip -qr ../wikeep-extension.zip . )
              echo "Built:  dist/"
              echo "Packed: wikeep-extension.zip"
            '';
          };

          wikeep-open-chrome = pkgs.writeShellApplication {
            name = "wikeep-open-chrome";
            runtimeInputs = [ node ] ++ linuxBrowserPackages;
            text = ''
              set -euo pipefail

              if [ ! -d dist ]; then
                echo "dist/ not found. Building first..."
                if [ -f package-lock.json ]; then npm ci; else npm install; fi
                npm run build
              fi

              PROFILE_DIR="$PWD/.chrome-dev-profile"
              EXTENSION_DIR="$PWD/dist"
              FLAGS=(
                "--user-data-dir=$PROFILE_DIR"
                "--disable-extensions-except=$EXTENSION_DIR"
                "--load-extension=$EXTENSION_DIR"
                "chrome://extensions"
              )

              # macOS: launch the system Google Chrome.
              if [ "$(uname)" = "Darwin" ]; then
                if [ -d "/Applications/Google Chrome.app" ]; then
                  exec open -na "Google Chrome" --args "''${FLAGS[@]}"
                fi
                echo "Google Chrome.app not found in /Applications."
                echo "Install Chrome, or load dist/ manually (see PLAN.md)."
                exit 1
              fi

              # Linux: prefer nix chromium, then system browsers.
              if command -v chromium >/dev/null 2>&1; then
                exec chromium "''${FLAGS[@]}"
              fi
              if command -v google-chrome >/dev/null 2>&1; then
                exec google-chrome "''${FLAGS[@]}"
              fi

              echo "No Chrome/Chromium found. Load dist/ manually (see PLAN.md)."
              exit 1
            '';
          };
        in
        {
          default = pkgs.mkShell {
            packages = [
              node
              pkgs.git
              pkgs.jq
              pkgs.zip
              pkgs.unzip
              wikeep-check
              wikeep-build
              wikeep-open-chrome
            ] ++ linuxBrowserPackages;

            shellHook = ''
              echo "Wikeep dev shell"
              echo "Node: $(node --version)   npm: $(npm --version)"
              echo
              echo "Commands:"
              echo "  npm ci / npm install   install dependencies"
              echo "  npm run typecheck      TypeScript check"
              echo "  npm test               Vitest (use -- --passWithNoTests if empty)"
              echo "  npm run build          build into dist/"
              echo "  wikeep-check           install + typecheck + test + build + manifest checks"
              echo "  wikeep-build           full validation + build + ZIP"
              echo "  wikeep-open-chrome     launch Chrome with dist/ loaded"
            '';
          };
        });
    };
}
```

### Pin it (this is what makes the setup reproducible)

```bash
nix flake lock      # generates flake.lock
git add flake.lock  # COMMIT it — the lock file is the pin
```

The `nixos-unstable` URL only decides what you get the *first* time you lock.
After `flake.lock` is committed, everyone resolves the exact same nixpkgs
revision until someone runs `nix flake update`.

## File 4 (optional): `.github/workflows/nix-check.yml`

```yaml
name: Nix Check

on:
  pull_request:
  push:
    branches: [main]

jobs:
  nix-check:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - name: Install Nix
        uses: DeterminateSystems/nix-installer-action@v16

      - name: Magic Nix Cache
        uses: DeterminateSystems/magic-nix-cache-action@v8

      # Evaluates the dev shell and runs shellcheck on the writeShellApplication
      # helpers. This is the intended meaning of "flake check" here.
      - name: Flake check
        run: nix flake check

      - name: Build + validate extension
        run: nix develop --command wikeep-build
```

> CI runs on Linux, so the Nix `chromium` path is exercised there; the macOS
> Chrome launch is a local‑only convenience and is not tested in CI.

## Delivery: standard Git + Pull Request

No GitHub Contents API needed. From a clean clone:

```bash
# 1. Branch
git checkout -b feat/nix-flake-dev-shell

# 2. Add the files (flake.nix, .envrc, .gitignore, optional workflow)
#    ...create them per the sections above...

# 3. Pin nixpkgs and validate locally BEFORE pushing
nix flake lock
nix develop --command wikeep-build   # full validation + build + ZIP

# 4. Commit (include flake.lock)
git add flake.nix flake.lock .envrc .gitignore \
        .github/workflows/nix-check.yml PLAN.md
git commit -m "Add reproducible Nix flake dev shell"

# 5. Push and open the PR
git push -u origin feat/nix-flake-dev-shell
gh pr create \
  --base main \
  --title "Add Nix flake development shell" \
  --body "Reproducible Nix dev environment for the Wikeep MV3 extension: pinned Node toolchain, typecheck/test/build helpers, built-manifest MV3 validation, macOS Chrome launch helper, ZIP packaging, and direnv integration. Tooling-only; no runtime changes."
```

Validating locally (step 3) before pushing is the key difference from the API
approach — the PR can't contain a flake that fails to evaluate.

## Local quick start (macOS)

```bash
git clone https://github.com/drunkod/wikeep.git
cd wikeep
nix develop            # or: direnv allow
npm ci || npm install
wikeep-check           # install + typecheck + test + build + manifest checks
wikeep-build           # also produces wikeep-extension.zip
wikeep-open-chrome     # launches Google Chrome with dist/ loaded
```

### Manual Chrome loading (if auto‑launch fails)

```bash
npm run build
```

Then in Chrome:

1. Open `chrome://extensions`
2. Enable **Developer mode**
3. Click **Load unpacked**
4. Select the `dist/` directory

## Acceptance criteria

- `nix develop` opens a working shell on `aarch64-darwin`.
- `node --version` and `npm --version` work inside the shell.
- `flake.lock` is committed (the environment is actually pinned).
- `wikeep-check` passes, including built‑manifest MV3 validation.
- `wikeep-build` produces `dist/` and `wikeep-extension.zip`.
- `wikeep-open-chrome` opens Google Chrome with the unpacked extension on macOS.
- The PR is created via `git` + `gh` and contains only tooling/docs changes.
